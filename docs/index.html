Patchery

When a dependency breaks your code,
Patchery fixes it and proves the fix.

A GitHub Action that reads the changelog, migrates the call sites, re-runs your own tests, and only then opens a pull request. It never trusts its own report — it verifies the diff itself.

View on GitHub Setup guide

How it works

  • 1. Run the tests. Is it actually broken? If it passes, do nothing.
  • 2. Run the agent. Read the changelog, migrate the affected call sites.
  • 3. Check with git. What changed? Touched a test file or a lockfile? Revert everything.
  • 4. Run the tests again. Never trust the agent's own word — measure it.
  • 5. Open a PR. Only if every step above came back clean.

See it work

A live, fully automated run: the agent found a real breaking change, fixed the one affected file, verified the tests went from failing to passing, and opened a pull request — no human in the loop until review.

Status

Patchery is early. It's a GitHub Action you install yourself today (.github/workflows/), not a hosted service yet. It has been run successfully against its own test fixture and is now being tried against real open-source projects — see the setup guide on GitHub for exact steps and current limitations, stated honestly.
