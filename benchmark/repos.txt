# Repositories to measure against. Chosen for being recognizable and genuinely
# tested, not for having a migration in their history - see find-bumps.mjs for
# why that constraint was dropped.
#
# A line is a GitHub owner/name, followed by what the project is:
#
#   library      other people install it and import it
#   application  it runs; nobody imports it (products, and tools that are
#                invoked rather than loaded)
#
# The label decides which fixes are honest, so it is written here rather than
# guessed from package.json. When a dependency starts shipping as an ES module,
# teaching the test runner to transform it is correct in an application and
# dishonest in a library, where it greens one CI and leaves every consumer
# broken. The agent refused exactly that on express, and was right.
#
# Guessing it from package.json was tried and got four wrong in the first run:
# express and multer declare no `main` (Node defaults to index.js), and lodash
# and zod set `private: true` at a root that still ships a library. An
# unlabelled line falls back to that heuristic, which now answers "unknown"
# rather than picking a side.
#
# Comments and blank lines are ignored.
#
# What earns a place here: a name a developer recognises, a real unit-test suite,
# and a `npm test` that runs in an empty container. That last one is not a
# formality - twelve of the first thirty-three verdicts were healthy projects
# whose tests wanted a database, a browser or a prepared machine, and every one
# of them came back looking like a broken repository.

# Applications, added 2026-09-07 - because the pool was measuring the wrong
# population.
#
# Thirteen of the first fourteen confirmed cases were libraries, and a library
# structurally cannot take the fix that most of those breaks need. When a
# dependency ships as an ES module, the honest fix is often to teach the test
# runner to transform it - correct in an application, dishonest in a library,
# where it greens one CI and leaves every consumer broken. The agent refused
# exactly that on express, and it was right; the row read NO-CHANGE.
#
# An application has no consumers to break. It is also who pays: the private
# repositories this is priced for are companies' products, not their libraries.
#
# TypeScript is wanted for a second reason. An API signature change breaks `tsc`
# even when no test exercises it - which is precisely the class the test-broke
# trigger misses today (express v4 -> v5 was invisible to five suites in a row).
#
# Many of these are monorepos and some will be rejected for wanting a database
# or a browser. That is the pipeline's job; a rejection recorded is cheaper than
# a candidate assumed.
